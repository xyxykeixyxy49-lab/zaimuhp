## 4. データベース設計（Notion）

```
[セミナー] 1 ──< [接点履歴] >── 1 [顧客]
```

### 顧客（1人1行）
氏名／フリガナ／会社名／役職／属性（経営者・研修担当者・税理士・公認会計士・個人事業主…）／メール／電話／都道府県／LINEユーザーID／LINE友だち／初回流入（ホームページ・公式LINE・紹介…）／**ステージ**／案内配信の同意／初回接点日／最終接点日／メモ

**ステージの順番**（後戻りしない）：
`LINE友だち → 資料請求 → 問い合わせ → セミナー申込 → 受講済み → リピーター → 法人契約`

- 「受講済み」「リピーター」「法人契約」は運営側が手動で更新する。
- 「接点履歴」の参加状況を「参加」にしたら、顧客を「受講済み」に上げる運用。

### 接点履歴（1アクション1行・自動記録）
件名／種別（セミナー申込・資料請求・問い合わせ・法人研修相談・LINE友だち追加・LINEブロック）／顧客／セミナー／経路（ホームページ・公式LINE）／対応状況（新規→対応中→完了）／参加状況（申込・参加・欠席・キャンセル）／参加人数／希望資料／内容／流入元／受付日時

### セミナー（運営側が入力）
タイトル／開催日／時間／会場区分（東京・大阪・名古屋・宇都宮・オンライン）／会場名／住所／定員／参加費／種別／対象／受付状況（受付中・残りわずか・満席・受付終了）／**公開**／決済リンク／概要

## 5. 公式LINE連携の流れ

```
HP ──(友だち追加ボタン)──▶ 公式LINE ──(follow Webhook)──▶ 顧客DB「LINE友だち」
公式LINE リッチメニュー ──▶ HPのフォームを LIFF で開く ──▶ 申込に LINEユーザーID を紐づけ
HP フォーム申込（メール）＋ 後日 LINE 内から申込 ──▶ 同じ顧客に統合（メール/LINE ID で名寄せ）
```

※ LINE で友だち追加しただけの人と、HPでメール申込した人は、LINE内（LIFF）で一度フォームを送るまで別人として登録される（LINEの仕様上、自動では結びつかない）。

## 6. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| フレームワーク | Astro 7 ＋ Tailwind CSS 4 | 表示が速くSEOに強い。必要なページだけサーバー処理 |
| ホスティング | Cloudflare（Workers） | 無料枠が大きく国内表示も高速。Turnstile と同居できる |
| データベース | Notion（既存のプロジェクトページ配下） | 普段使いの画面で顧客・申込を確認・編集できる |
| メール | Resend | 独自ドメインから送信でき、設定が簡単 |
| LINE | Messaging API ＋ LIFF | 友だち追加の記録と、LINE内申込の紐づけ |
